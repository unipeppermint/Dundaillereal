# 首版实现说明

更新：2026-09-20。01～03 为设计基线；当前实现与验证以本页和 05-validation.md 为准。

## 运行

打开 `Dundaillereal.xcodeproj`，选共享 Scheme `Dundaillereal`，选择 iPhone 模拟器后运行。Swift + UIKit，应用 Target 最低 iOS 16，iPhone 竖屏。没有第三方包或后台。原应用 Bundle ID、签名团队和 Release 构建设置保持原值；仅去掉已弃用的 Main storyboard 启动键，注册玩法文件类型并添加测试 Target。

命令行：

```sh
./scripts/test-core.sh
xcodebuild -project Dundaillereal.xcodeproj -scheme Dundaillereal \
  -configuration Debug -sdk iphonesimulator \
  -derivedDataPath /tmp/DiceWorkshopBuild CODE_SIGNING_ALLOWED=NO build
xcodebuild -project Dundaillereal.xcodeproj -scheme Dundaillereal \
  -configuration Debug -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -derivedDataPath /tmp/DiceWorkshopBuild CODE_SIGNING_ALLOWED=NO test
```

真机运行需要项目原有团队的有效开发签名，不在本次自动配置范围。

## 已实现范围

- 游戏桌：继续正式存档、三套内置游戏、最近玩过、创作入口。
- 1～4 人玩家设置、规则说明、动态站点棋盘、准确绘制的骰子、选择/保留/重掷、自动计分解释、玩家轮转、结算及并列结果。
- 单人同规则个人最佳；最近 100 场正式历史。试玩不写正式存档或历史。
- 工坊：复制模板、新建、实时参数校验与自然语言说明、保存、编辑、试玩、删除。
- 收藏柜：收藏作品、导入作品、对局记录及结果详情。
- 分享 `.dicework` JSON 与动态排版规则图片；系统文件选择、外部“打开方式”接收、校验及导入预览。导入生成新 ID，不覆盖作品。
- 设置：声音、触感、资料重新载入。大字体、旁白标签、减少动态效果；键盘跟随布局及完成输入按钮。
- 独立生成的装饰插画、代码动态绘制的棋盘与纸质骰子；原创程序绘制应用图标。没有把原型截图嵌入操作界面。
- 空状态、非法规则、超限文件、版本不兼容、存储失败和损坏备份恢复提示。

## 三套规则的定稿

《恰好到站》采用产品方案全部建议默认值：3 颗骰子；目标 6/8/10/12/14/16；6 轮；每人整局单颗重掷 2 次；精准 3 分、差 1 得 1 分；0 分也消耗站点；连续精准 3 次加 2 分后归零，非精准中断。允许并列。单颗重掷后清空所选骰子组合，但保留目标选择。

《留点好运》：默认 5 颗骰子、6 轮。每次初掷后可保留任意骰子，重掷所有未保留骰子，每回合最多 2 次。保留可自由切换，也可直接结算。计分使用全部骰子点数总和，再按不重叠的同点对子每对加 2 分：3 颗相同算 1 对，4/5 颗相同算 2 对。不存在强制保留点数，以选择保留为策略核心。

《见好就收》：默认每次 2 颗骰子、6 轮。每次出现任意 1 点立即爆仓，本回合 0 分；否则点数累加到背包。玩家可收手或继续投；每回合最多 5 次，达到上限自动入账。收手和爆仓均需确认交接到下一位，避免同机玩家误操作。不存在无限轮次或无限投掷。

受限参数范围在 `Definition.validate()` 中统一定义：骰子 1～5、轮数 1～12、重掷 0～5、精准分 1～10、相差分 0～5、连击阈值 2～6、奖励 0～10、风险面 1～6、冒险投掷上限 2～8。站点数等于轮数、互不重复且在 1～骰子数×6；该范围内每个目标均可用允许数量的六面骰子组合达到。校验通过不意味着玩法平衡已被用户试玩证明。

## 数据与安全边界

`Domain/Game.swift` 是不依赖 UIKit 的规则引擎。随机数可注入，生产使用系统均匀随机整数；先计算、原子保存成功，再展示和动画。每个操作附修订号，重复提交被拒绝；非法操作在临时值上执行，不污染旧状态。

`Data/Store.swift` 使用串行队列、Codable JSON、原子写入及上一份备份。首版将作品、收藏、唯一正式存档和历史放入同一个 Application Support/DiceWorkshop/library.json，以同一事务保证结束入档与清除继续槽的一致性（相比设计中的逐作品文件，这是有意简化）。写失败不发布候选状态；再次操作可重试。启动读取失败时保留损坏副本、验证备份并恢复；无可靠备份则保留资料并禁用写入，仍可试玩。历史按会话 ID 去重。

格式和模板版本均为 1；目前没有历史版本需要迁移。未知版本明确拒绝。编辑作品不修改会话快照。正式新开局覆盖旧局前有确认。

文件限制为 1 MB，先检查元信息，再受限读取最多 1 MB + 1 字节。名称 1～40 字；只允许已知模板及有界参数。封面由模板枚举确定，没有外部图片或脚本。导出不带玩家、历史或存档。测试模式仅在 DEBUG 启用，使用独立临时目录，不接触正式资料。

## 真实剩余限制

- 已完成自动化规则模拟与 UI 流程验证，但尚未做目标用户参与的平衡性试玩；不能将自动测试等同于“经过用户验证的好玩”。
- 当前环境只有 iOS 26.5 模拟器；最低 iOS 16 的编译兼容性已配置，尚无对应运行时做运行回归。
- 未进行真机触感、音量/静音表现、AirDrop/第三方分享渠道、文件 App 外部接收的完整真机验证。
- 2026-09-21 已加入独立山水位图、封面与二维骰子，详见 06-visual-upgrade.md；不包含完整 3D、联机、社区、云同步、AI 规则或购买流程。
- 导航为轻量页面控制器；尚未引入独立 MVVM/Coordinator 层。保存使用串行同步提交，小规模离线资料足够，若未来扩大历史量需改异步 UI 提交。
- 历史最多保留 100 场；个人最佳按模板及规则配置独立持久化，不随历史淘汰。作品库保护上限 1000 个，不做付费槽位限制。
