# 骰子工坊 · 产品方案

## 1. 定位

一句话：用几颗骰子，创造一场属于你的桌游。

产品提供可以直接玩的原创轻桌游，以及基于模板修改规则的工坊。用户能完成“设定规则 → 自动主持对局 → 看懂得分 → 调整规则 → 分享作品”的完整过程。

首批用户是喜欢轻桌游的朋友、情侣和家庭。典型场景为饭后、等人、旅行途中，用一部手机玩一局约 3～8 分钟的游戏。专业桌游设计能力不作为首版目标。

## 2. 差异化依据

本次有限竞品检索发现，3D 投骰、多面骰、材质主题、自定义文字或照片骰面、概率统计等功能已有产品覆盖。差异化应集中在可玩的规则作品、自动主持和改编体验上，不将单个常见功能视为独特性证明。

| 参考产品 | 可见功能 | 对本产品的启示 |
| --- | --- | --- |
| [Dice-Roll](https://apps.apple.com/us/app/dice-roll/id6801032488) | 多面骰、3D 投骰、桌面和材质 | 投骰表现是基础体验 |
| [DicePlay](https://apps.apple.com/us/app/diceplay-roll-anything/id6774099074) | 自定义骰面、锁定与重掷 | 自定义骰面不足以独立形成定位 |
| [Pro Roller](https://apps.apple.com/us/app/pro-roller/id1637384979) | 概率模拟、统计、自定义事件 | 统计页不是主要差异化方向 |

检索日期为 2026-09-20，未进行全市场穷尽检索，不声称不存在类似产品。

## 3. 使用模式

- 单人：挑战内置游戏，设计规则并试玩。
- 同机多人：2～4 人轮流操作同一部手机，自动提示玩家并计分。
- 分享：通过系统分享发送玩法文件；接收者安装应用并导入后独立游玩。
- 全部核心玩法离线可用，无须注册。文件传输是否联网取决于用户选择的分享渠道。

首版不包含实时房间、远程对战、账号和排行榜。单人结果显示得分与完成情况，不使用“击败其他玩家”的结算文案。

## 4. 产品结构

| 主导航 | 内容 |
| --- | --- |
| 游戏桌 | 继续上局、内置原创游戏、最近玩过、创作入口 |
| 工坊 | 我的作品、从模板新建、复制改编、规则编辑、试玩 |
| 收藏柜 | 收藏和导入的作品、对局记录 |

初次使用优先展示可直接开始的游戏，完成一局后提供“改成我的玩法”。作品详情承载玩法说明、开始游戏、编辑和分享。

## 5. 核心能力

### 可执行的规则卡

编辑器通过模板支持的参数修改骰子配置、回合动作、得分、奖励和结束条件；同步显示自然语言说明。校验缺失条件、参数越界和已知不可达的目标。

首版采用受限模板，不支持任意脚本或跨模板自由组合。用户只能保存和试玩引擎支持的有效配置。

### 自动主持

负责投骰、选择保留或重掷、当前玩家提示、计分解释、回合推进和终局结算。每一次得分有可理解的理由，避免让玩家自行计算。

### 作品保存与分享

作品包含名称、模板、参数、封面标识和版本。支持导出规则图片及可导入的玩法文件。修改已有作品时，已开始的对局继续使用开局时的规则。

## 6. 内置玩法

### 《恰好到站》：第一阶段开发对象

玩法概念：每人有六个目标站点，投掷三颗骰子，通过选择骰子组合完成站点，在有限重掷机会下争取高分。

为了补齐讨论中未明确的边界，提出以下开发建议，正式定稿前需试玩：

| 项目 | 建议默认值与定义 |
| --- | --- |
| 人数 | 1～4 人 |
| 骰子 | 3 颗公平六面骰 |
| 站点 | 6、8、10、12、14、16，每人独立一张路线 |
| 轮次 | 共 6 轮，每轮每位玩家各行动一次 |
| 选择 | 选择至少一颗骰子，点数之和用于一个未填写站点 |
| 重掷 | 每位玩家整局 2 次，每次重掷 1 颗骰子；重掷后重新选择组合 |
| 计分 | 总和恰好等于目标得 3 分，相差 1 得 1 分，否则 0 分 |
| 站点消耗 | 确认后该站点即被填写，0 分也消耗；每次行动必须完成一个站点 |
| 连续奖励 | 按行动时间计算，连续精准命中达到 3 次奖励 2 分，随后连击归零；未精准命中则中断 |
| 平局 | 允许并列获胜 |
| 单人 | 展示总分、精准命中数和本地个人最佳成绩 |

示例：选择骰子 2、3、5，总和为 10，填入目标 10 的站点，获得 3 分。连击按本人的行动序列计算，不受其他玩家回合影响。

需验证：目标分布、单局长度、重掷额度、先后手体验、奖励强度，以及是否存在明显单一最优策略。

### 其余两套模板：设计阶段

- 《留点好运》：强调保留与重掷；可配置骰子数量、保留条件、重掷上限和计分组合。
- 《见好就收》：强调风险与收手；可配置风险条件、奖励、收手规则和结束条件。

这两套目前只有玩法方向，具体规则和完整状态流程尚未定稿；实现前需分别形成规则表并试玩，不能直接视为已完成设计。

## 7. 首版范围

必须完成：3 套经过试玩的内置玩法、受限规则编辑、同机多人、自动计分解释、暂停恢复、作品保存、规则图片与文件分享、导入校验、离线使用。

后续候选：相同随机条件挑战、iPad 专门布局、更多模板、云同步、实时联机。相同随机条件挑战需要单独设计随机序列与玩法版本兼容，首版不承诺支持。

商业化建议为免费体验加一次性解锁高级工坊：内置游戏完整可玩，免费自建槽位有限，付费增加槽位和高级规则。槽位数量、价格和是否在 1.0 接入付费均待确定，不阻塞核心原型开发。

## 8. 审核与展示

苹果审核指南 4.3 涉及重复应用及难以区分的体验，4.2 涉及最低功能要求。应通过独立内容和完整功能体现价值，不保证审核结果。[苹果审核指南](https://developer.apple.com/app-store/review/guidelines/)

- 首页直接展示原创游戏和创作入口。
- 商店截图展示改规则、玩一局、自动结算和导出作品。
- 审核备注提供可操作路径：打开《恰好到站》→完成一次行动→查看计分解释→改编目标数字→试玩。
- 代码、规则文案和美术独立制作；新增玩法集中在同一应用更新。
- 提交前完成可运行版本、真实用户试玩和完整商店素材。

## 9. 阶段与验收

按一名熟悉 iOS 的开发者、轻量美术和无后台估计，约 6～8 周，不含审核等待。复杂插画制作及玩法反复调整可能增加工期。

| 阶段 | 估计 | 可验收结果 |
| --- | --- | --- |
| 玩法验证 | 1 周 | 规则边界明确，目标用户能理解并完成一局 |
| 核心对局 | 2 周 | 主玩法完整运行，计分正确，中断后能继续 |
| 工坊与扩展 | 2 周 | 修改有效参数后能试玩，补齐其他模板和分享流程 |
| 打磨提交 | 1～3 周 | 视觉、音效、可访问性、设备测试和提交素材完成 |

产品验证重点：首次开局是否顺畅、能否独立完成一局、是否愿意修改一条规则再玩、分享后能否成功导入。首版可通过观察试玩和访谈验证，不预设需要远程埋点服务。
