Rollweave: Slot Atelier is a dice tabletop game and rule workshop for 1-4 players taking turns on one iPhone. Native gameplay works offline. No account, sign-in, subscription, or in-app purchase is required for these games.

NETWORK SERVICES AND PERMISSIONS

1. Privacy policy address service
At startup, the app sends a POST request to https://ketwtyajxw.top/v2/api/user/login with a fixed application identifier. Despite the endpoint name, this is not a user sign-in flow and does not send player credentials, names, or scores. Its configured business purpose is to obtain the privacy policy address.

For transparency, the current startup handler also uses a locally cached web address. If the response URL contains "rollweave", the app opens the native interface when there is no cached URL, or loads the cached URL when one exists. Other valid HTTP(S) response URLs are saved and opened in an embedded web view. Request failures use the cached URL, or the native interface if no cache exists. Successful web navigation also updates the cached address. The web view is not restricted to a single policy domain.

The policy is also available from Settings > Privacy Policy:
https://tkzcpoj.netlify.app/rollweave/privacy-policy/

2. Meta advertising measurement
The app includes Meta's SDK for install and app-activation measurement associated with our advertising campaigns. The app initializes this SDK only while active and after App Tracking Transparency authorization. It disables automatic app-event logging, automatic event flushing, and SKAdNetwork reporting. The app does not submit purchase, cart, wish-list, or registration events through its web bridge. Native gameplay does not require tracking permission. On detecting revoked authorization, the app disables further app-initiated measurement; already transmitted data is not recalled.

3. Firebase Cloud Messaging and APNs
The app registers with Firebase/APNs for remote notifications intended for version updates, feature updates, and important service notices. Notification alerts require separate system permission. Firebase initialization and token registration are independent of the alert permission. Push identifiers are not supplied by our app to Meta or associated with local player names or scores.

4. Local Messages page
Settings > Messages shows one bundled welcome message. It is not a Firebase inbox, user-to-user chat, or a record of received remote pushes. No banner is generated for this local message.

REVIEW STEPS

1. In the native interface, open Games > Right on Track > Start Game, choose players, then Begin. Roll dice, choose dice and a target stop, then Confirm Stop.
2. Open Workshop > Create from Right on Track. Edit a supported setting, select Playtest Rules, then return and Save Game.
3. Open a saved game's details and Share Game. Save the .dicework file to Files, then use Workshop > Import a .dicework File to import it.
4. Try Lucky Pairs and Bank or Bust. Reopen an unfinished regular game using Resume Game. Completed games appear in Collection.
5. Open Settings > Messages and Settings > Privacy Policy. Tracking and notification permissions can be managed separately in iOS Settings. Denying these permissions does not disable native games.

Player names, rules, progress, and scores remain on the device unless the user shares a file through the system share sheet. Scores are points only: no wagers, purchased chips, cash prizes, cash-out, or loot boxes.
