## 1. 项目现状与约束

2026-09-20 检查结果：当前为 UIKit 空项目，包含 AppDelegate、SceneDelegate、ViewController；使用 Main storyboard 启动。App Target 设置为 iOS 16.0、iPhone、竖屏、Swift 5 语言模式。项目级最低系统值为 26.5，App Target 有自己的 16.0 覆盖值，实施时应检查最终生效设置。开发环境为 Xcode 26.6（17F113）。

| 模块 | 选择 |

```text

Features/
  GameTable/         游戏桌

  Collection/        收藏、导入作品、历史

  Models/            作品、配置、状态、计分结果
```

以上为计划结构，尚未创建代码模块。引擎与数据结构保持独立，首版无需为其拆分多个独立 package。

## 4. 引擎设计

对局状态流为：准备 → 等待投骰 → 选择与重掷 → 选择目标 → 确认计分 → 下一位玩家 / 结束。选择骰子和目标可以在确认前调整。

UI 提交类型化 Action，引擎检查当前阶段、玩家和额度，然后输出新状态与事件。得分数值和解释均从同一 ScoreBreakdown 生成。动画只消费结果，不参与计分与随机判定。

- 投骰时先取得结果并保存新状态，再播放动画。
- 动画中禁止重复提交；引擎本身也拒绝不合法操作。
- 确认动作包含状态修订号或操作标识，避免重复确认产生双重计分。
- 切后台或重启后，直接显示已保存结果，不重新抽取。
- UI 更新在主线程；文件 IO 通过专用 actor 或串行队列执行。
- 持久化失败时保留旧的可靠快照，提示重试；不能显示“已保存”或静默放行下一次改变状态的操作。

普通对局使用系统随机源，通过有界随机 API 生成 1…6，避免自行使用取模映射。测试注入固定结果。首版不实现基于种子的挑战；未来实现需定义算法及版本，不能依赖标准库跨版本产生相同序列。[RandomNumberGenerator 文档](https://developer.apple.com/documentation/Swift/RandomNumberGenerator)

## 5. 模板与编辑器

GameTemplate 定义模板标识、可编辑参数、默认配置、校验、计分和呈现类型。规则采用有类型的配置结构，避免任意字符串公式和脚本执行。

首版通过复制模板后修改参数来创作。每种模板独立完成规则表和单元测试；编辑器只展示对应模板支持的字段。对范围内的小规模骰子组合，可枚举检查目标是否可达；不承诺对任意规则证明平衡性。

正式开局、编辑器试玩和导入作品必须走同一校验入口。试玩使用临时会话，不覆盖正式继续上局槽位。

## 6. 数据模型

| 模型 | 关键字段 |
| --- | --- |
| GameDefinition | id、name、templateID、templateVersion、parameters、coverID、createdAt、updatedAt |
| GameSession | id、规则快照、players、status、stateRevision、createdAt |
| GameState | 当前轮次、玩家索引、骰子结果与选择、各玩家棋盘和额度、当前阶段 |
| ScoreBreakdown | 基础得分、奖励、原因代码、关联行动 |
| GameRecord | 结束时间、规则摘要、最终成绩、关键统计 |
| LibraryMetadata | 收藏标识、来源、最近游玩时间 |

保存文件另带 schemaVersion，与模板版本分开管理。作品编辑不会修改进行中的规则快照。计分原因保存结构化代码和数值，显示文案由应用生成。

## 7. 存储与恢复

- 内置模板为只读资源，用户改编生成新的作品 ID。
- 自建作品按 ID 分文件保存；正式会话使用一个完整快照文件。
- 首版只保留一场可继续的正式对局。新开局前明确处理已有对局，不静默覆盖。
- 每次有效状态变化后顺序保存，采用原子替换并保留上一份可靠快照。
- 历史记录按会话 ID 去重，恢复时避免重复追加已结束对局。
- 用户数据位于 Application Support；导出临时文件放缓存或临时目录，可重新生成。
- 版本升级提供已知格式迁移；遇到较新未知格式给出可理解提示，不尝试猜测解析。
- 读取损坏文件时尝试上一份备份，保留损坏副本用于恢复，不自动清空整个资料库。

[FileManager 原子替换相关文档](https://developer.apple.com/documentation/foundation/filemanager/replaceitemat(_:withitemat:backupitemname:options:))

## 8. 文件导入导出

暂定扩展名 `.dicework`，使用自定义导出 UTType，载荷为 JSON：格式版本、模板标识及版本、名称、参数、内置封面标识。注册 UTType 不需要更改 Bundle ID。

首版仅引用内置封面，不携带任意图片或压缩包。建议限制文件大小 1 MB、作品名称 40 个字符，具体参数上限按模板定义；这些为实现建议。

导入流程：取得文件访问权限 → 受限读取 → 解析版本 → 校验模板与参数 → 预览 → 作为新作品导入。遇到重复名称允许改名，不能覆盖原作品。玩家信息、成绩和正式存档不进入分享文件。

规则图片由真实规则数据排版绘制，确保与实际玩法一致。图片是说明材料，可导入的文件才承载完整可执行配置。

## 9. UI 与可访问性

三栏底部导航承载主页面；对局页隐藏底部导航。棋盘根据容器尺寸布局，规则页使用可滚动列表，主操作遵循安全区。

插画与状态图层分开，避免将生成原型作为整张背景覆盖控件。DiceView 必须展示引擎指定的准确点数；VoiceOver 提供点数、选中状态、站点目标和得分。支持减少动态效果，音效和触感可关闭，大字体下关键操作仍可见。

## 10. 实施与验证

| 顺序 | 工作 | 验收重点 |
| --- | --- | --- |
| 1 | 主玩法模型、规则、引擎和简版 UI | 单人及多人能完整结束，计分符合规则表 |
| 2 | 本地存档、恢复、正式对局与试玩隔离 | 中断不重抽、不重复计分、不覆盖正式进度 |
| 3 | 规则编辑与作品库 | 有效改编可玩，无效参数有明确提示 |
| 4 | 补齐两套模板、导入导出 | 各模板规则先定稿，分享往返后参数一致 |
| 5 | 插画动画、声音触感、可访问性 | 最小屏幕可用，减少动态效果正确 |
| 6 | 发布准备和可选付费 | 完整回归、商店素材、购买恢复（若启用） |

单元测试集中于有业务风险的逻辑：骰子组合、计分边界、每位玩家的重掷额度、连击重置、轮次推进、平局、重复操作、规则校验、存档迁移和损坏文件处理。UI 测试覆盖开局至结算、改编试玩和恢复路径。

实施后执行模拟器 Debug 构建、核心测试和必要的真机检查；最低 iOS 16 与当前系统分别验证，真机验证音效、触感和文件分享。若环境缺少对应系统运行时，应明确报告未覆盖项，不声称已通过。
